# LightGBM 和「AI」到底差在哪（一页纸）

> 用途：面试被问「你怎么看 LightGBM 和 AI 的关系」时的答案；也写给第一次接触的人。
> 所有读数来自本仓：`data/results.json` · `data/judge_efficiency.json` · `data/rolling_daily_2024.json`。

## 一句话

**先把「AI」拆开** —— 它现在装了三种完全不同的东西：经典机器学习（LightGBM 在这里）· 深度学习 · 大语言模型。
**关键差别不是「算不算 AI」，而是两件事：特征谁来找 + 能被问什么。**

## 1. 三个层次

| | 是什么 | 特征 | 能被问什么 |
|---|---|---|---|
| **经典机器学习**（LightGBM） | 梯度提升决策树 | **人给**（我们手工造了 65 列） | 只有一个问题：「这一行，像不像以前亏过的公司？」 |
| **深度学习 / 神经网络** | 从原始数据自学表示 | 模型自己学 | 图像 / 语音 / 大规模序列 |
| **大语言模型**（本会话里的我） | 从文本里学 | 语料 | 什么都能问，答得好不好另说 |

## 2. 四个能一眼看出的差别（都有本仓实测）

| 维度 | LightGBM（实测） | 大语言模型 |
|---|---|---|
| 输入 | **一张表**（65 列 × 19,473 行） | 文本、PDF、代码…… |
| 输出 | **一个分数** | 一段话（要再解析） |
| 速度 | 单条 **p50 2.01 ms / p95 2.21 ms**；批量 **29.97 万行/秒**；四折训练+预测 **3.2 秒** | 秒级～几十秒/条 |
| 成本 | 边际成本≈电费；跑一万次也是秒级 | 按 token 计费 |
| **复算性** | **同输入重跑逐位一致**（本仓每条读数都能被别人重算） | 不保证一致（换版本/换采样都会变） |
| 会不会读公告 | **不会** —— 今天那 211 份戴帽公告、1,255 份修正公告是**我**读的 | 会 |

## 3. 「当机械工具用」——一半对

- **对的那半**：它确实机械。给定种子与数据，它每次都吐一样的数；它没有想法，也不认为自己在预测什么。
- **不对的那半**：它不是「你写好的规则」。如果机械工具是锤子，**它更像一把量具** —— 一支形状很特定的尺子，
  只量一件事：「这家公司像不像以前亏过钱的」。**尺子读数好不好，取决于你把它对准了什么。**
  ⇒ 这就是本仓的全部主题：**模型没问题，出问题的是喂给它的东西**（偷看一期 +3.4 分 · 随机切分 +1.24 分 · 日期字段晚 365 天）。

## 4. 怎么用它（三层，一层比一层不像「跑个模型」）

1. **当计算器**：给一行，出一个数。就这么多。
2. **当排序机**（真身）：它不回答「会不会亏」，它**排序**；而**名单大小是比模型强弱更强的旋钮**
   （前 10% 覆盖 35.9% → 前 20% 覆盖 61.9%；前 50% 覆盖 94.9%）。
3. **当决策回路里的一个零件，不是决策者**：模型给**观察名单** → 公告**确认或解除** → 人做动作。
   实测：名单里约 **96%** 的公司会被公告明确兑现或解除，且每次变化都能指回一条公告。

## 5. 校准：词是营销的还是可量的？

- 本仓的分数**摊得开**（**29.07%** 落在不确定带 [0.2, 0.8]），但**没校准**：0.3–0.4 箱预测 34.96% / 实际 **54.31%**，
  0.6–0.7 箱预测 65.42% / 实际 **79.40%**（**系统性低估**）；
- 补一次 isotonic（拟合在验证折上）：**Brier 0.1009 → 0.0957**，各箱预测均值基本贴上实际频率 ⇒ **校准是能补的，代价是留一个验证折**；
- 对照：第三方对某个生成式 LLM 的同类实测里，它的概率**全落在 0.0/1.0**（107 例中仅 1 例"犹豫"），
  且**它答错的 5 例概率是 1.0 / 1.0 / 0.95 / 0.0 / 0.2** ⇒ **「阈值 0.8 转人工」这类流程在它身上跑不起来**。
- ⇒ **「校准」不是形容词，是一条可判的读数**（不确定带占比 + 分箱 reliability + Brier）。报模型好坏之前先问它这一格。

## 6. 分工（今天这一天的实际样子）

| 谁 | 干了什么 | 为什么只能是它 |
|---|---|---|
| **我（LLM）** | 读 1,255 份修正公告判方向、211 份戴帽公告归类、发现 +365 天日期坑、在自己写的回放里发现 PIT 闸门漏了一道 | 处理非结构化文本 + 判断"该量什么" |
| **LightGBM** | 19,473 × 65 列，稳定排出一个**能被别人复算**的次序（AUC 0.9103，逐年 0.891–0.928） | 精确、快、便宜、可复算 |

**两个都在用，但谁是主体很清楚：我出判据，它出数。**
