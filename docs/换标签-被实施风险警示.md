# 换标签：从「当年年报亏损」换成「被实施风险警示（*ST / ST）」

> 起因：现在的标签是个**会计结果**；业务真正要拦的是**监管动作** —— 被实施风险警示。
> 判据：`scripts/fetch_st_events.py`（取数）· `src/st_label.py`（事件与标签）·
> `src/run_experiments_st.py`（换标签重跑）· `src/diag_st_negative_control.py`（负对照，5 种子）。读数落 `data/results_st_label.json` 等。

## 1. 标签怎么做出来的（可时点化）

- **来源**：巨潮公告检索，`keyword=风险警示`，逐年取（2015–2026，12 次调用，8,227 条公告）。
- **为什么要走这条路**：新浪的「曾用名」接口**只有名字、没有日期**（`000004` 能看到 16 个曾用名，
  但一个日期都没有）⇒ 还原不出「某年某日是不是 ST」。而公告**每条都带公告时间**，可时点化。
- **判据处理**（标题文字游戏很多，逐类分开）：含「风险警示」+「实施」且**不含**
  「撤销 / 进展 / 继续 / 提示 / 措施」⇒ 一次**新的戴帽事件**。
  ⚠️ 不这么筛的话会灌水 4 倍：2024 年「实施」类 666 条里 **538 条是进展公告**。
- **结果**：**952 次戴帽事件 · 606 家公司**，逐年 33（2015）→ 40 → 44 → 64 → 86 → 95 → 77 → 82 → 109 → **149（2025）** → 133（2026 至 9 月）。

## 2. 它有多稀有（这是换标签的代价）

| 标签 | 测试年正例率 | 正例数 |
|---|---|---|
| 当年年报亏损 | **23.91%** | 4,656 |
| 年报披露后 **90 天内**被戴帽 | **0.88%** | 172 |
| 年报披露后 **一年内**被戴帽 | 1.38% | 268 |

⇒ **两套标签量的是两件事**：4,747 个亏损样本里，只有 **148 个（3.1%）**在年报披露后 90 天内被戴帽 ——
因为 ST 通常要**连续两年**亏损才触发。**ST 是个比亏损晚一年左右的滞后事件。**

## 3. 换标签之后，模型读数怎么变（同一条流水线，只换 `label`）

| | ① 当年年报亏损 | ② 90 天内被戴帽 | ③ 一年内被戴帽 |
|---|---|---|---|
| A 诚实 · pooled AUC | **0.9103** | 0.8133 | 0.8000 |
| A 诚实 · macro AUC | 0.9095 | **0.8216** | 0.8132 |
| 逐年 AUC | 0.891 / 0.896 / 0.922 / 0.928 | 0.906 / 0.761 / 0.805 / 0.815 | 0.864 / 0.800 / 0.792 / 0.796 |
| 基线（上年是否亏损） | 0.7500 | 0.7362 | 0.7314 |
| 前 10% 名单精确率 | 84.78% | **3.91%** | **6.41%** |
| 基准率 | 23.78% | 0.87% | 1.36% |
| **lift** | 3.59× | **4.89×** | **4.86×** |
| **前 10% 名单召回** | 35.93% | **48.91%** | 48.60% |

**三条读法**：

1. **AUC 掉了（0.91 → 0.81），但排序能力其实更强**：看**召回** —— 前 10% 名单现在抓住了 **49%** 的所有戴帽事件，
   而换标签前只抓住 36% 的亏损公司。**lift 也从 3.6× 升到 4.9×**（名单里 3.91% 会戴帽，基准率 0.87%）。
   ⇒ 「AUC 变低」和「名单更管用」可以同时成立：**目标越稀有，AUC 越难高，但前 10% 名单的相对价值越高。**
2. **精确率从 84.78% 掉到 3.91% 不是模型变差**，是**分母换了**：戴帽的公司本来就少（每年约 43–74 家）。
   业务上要看的是 lift 与召回，不是精确率的绝对值。
3. **逐年 AUC 抖得厉害**（0.76–0.91）：每年只有 20–74 个正例 —— 这是**样本量**问题，不是模型问题；
   要报这张表就得同时报正例数。

## 4. 顺手抓到的一个方法论坑：负对照必须看 **macro**，不能看 pooled

打乱训练标签、5 个种子（`src/diag_st_negative_control.py`）：

| 标签 | pooled AUC | **macro AUC** |
|---|---|---|
| 当年年报亏损（4,656 正例） | **0.5553 ± 0.0051** | **0.5262 ± 0.0181** |
| 90 天内被戴帽（172 正例） | **0.4072 ± 0.0151** | **0.5006 ± 0.0418** |
| 一年内被戴帽（268 正例） | 0.4024 ± 0.0126 | **0.4950 ± 0.0386** |

**一个完全没有信号的模型，pooled AUC 能被读到 0.555（偏高）或 0.40（偏低）；macro 口径下才回到 0.5。**
原因是**跨年的刻度差**（各年基准率不同，pooled 把不同总体混在一起算）。
⇒ **负对照要给分布、并且要用 macro 口径读** —— 用 pooled 读负对照，会把"没有信号"读成"有信号"或"反着有信号"。
（这条与 `docs/口径.md` 里 "pooled vs macro" 那一条是同一件事，这次由负对照直接演示出来。）

## 5. 结论与边界

- ✅ **可行且更贴业务**：ST 标签可时点化、可复算，且**前 10% 名单的召回（49%）明显高于亏损标签（36%）**；
- ⚠️ **但太稀有**：每年正例 20–74 个 ⇒ 单年读数不稳，**只能合并四年报**，且任何单年差异都不能下结论；
- ⚠️ **ST 与亏损不是同一件事**：ST 滞后于亏损（同 90 天内只有 3.1% 的亏损样本被戴帽）；
  两套标签的结论**互为补充**，不是替代 —— 本作品的主表仍以「年报亏损」为准（样本量够），ST 作为**第二组读数**；
- ❓ 未做：把 ST 与亏损做成**两个头**（multi-task）或做**联合名单**（谁会亏 ∪ 谁会戴帽），
  那是另一个问题；也还没试「亏损 + 次年戴帽」这种两段式标签。
