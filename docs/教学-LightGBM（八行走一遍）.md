# LightGBM 是怎么运作的：八行数据走一遍

> 教具，不是实验。所有数字都由 `python src/tutorial_gbdt_8rows.py` 现算（读数落 `data/tutorial_gbdt.json`），
> 超参故意开到最小：**3 棵树 · 每棵只分裂一次 · 学习率 0.5** —— 每一步都手算得出来。

## 六步

1. **把问题变成一张表**：每行一个样本（公司-年），几列特征，一列标签。
2. **从"谁都不知道"开始**：初始分数 = 常数（这里正例率 50% ⇒ 分数 0 ⇒ 概率 0.5）。
3. **算"还差多少"**：`残差 = 真值 y − 当前概率 p`（对 logloss，这就是梯度）。
4. **长一棵小树去拟合残差**：树学的不是标签，是"上一轮还错的那部分"。
5. **小心地加上去**：叶子值 × 学习率（0.5），加到分数上。
6. **重复 N 轮**，最后把**所有树加起来** → 分数 → `sigmoid` → 概率 → 排序 / 切阈值。

## 三棵树长什么样

```
第 1 棵：ROA% ≤ 4.000 ?
     是 → 加 +0.6000 分（5 条样本）      ← D E F G H
     否 → 加 −1.0000 分（3 条样本）      ← A B C
第 2 棵：ROA% ≤ 4.000 ?（同一个切分，因为剩下的错还集中在这条线上）
     是 → 加 +0.3373 分
     否 → 加 −0.6839 分
第 3 棵：应收占比% ≤ 47.500 ?
     是 → 加 −0.3118 分                  ← 6 条
     否 → 加 +0.6958 分                  ← F H（两个真亏、但一直被打低分的）
```

**第一棵树只学到了一件事：ROA 低于 4 就可能亏。** 它把 D 也一起打进"亏"那侧（D 其实是好的）——
所以第二棵继续修这条线；第三棵才用第二个特征去救 F、H（它们 ROA 不算太低，但应收占比很高）。

## 手算验一下叶子值（这是"梯度提升"三个字真正的意思）

第 1 棵、左叶子（5 条样本，标签 `0,1,1,1,1`）：

```
当前 p 全是 0.5 ⇒ 残差 y−p = −0.5,+0.5,+0.5,+0.5,+0.5   （和 = +1.5）
曲率   Σ p(1−p) = 5 × 0.25 = 1.25
叶子值 = 残差和 / 曲率和 = 1.5 / 1.25 = 1.2
乘学习率 0.5 ⇒ +0.6      ← 与上面输出一致 ✓
```

右叶子（3 条样本，标签全 0）：`Σ(y−p) = −1.5`，`Σp(1−p) = 0.75` ⇒ `−2.0 × 0.5 = −1.0` ✓

第 2 棵、左叶子：p 已经升到 0.646 ⇒ 残差和 +0.7715、曲率和 1.1435 ⇒ `0.6747 × 0.5 = 0.3373` ✓

⇒ **树学的永远是"当前还差多少"，不是标签本身**；`分母是曲率`（二阶信息）就是 LightGBM / XGBoost
比"只用残差"的老 GBDT 收敛快的原因。

## 三个真正要紧的旋钮

| 旋钮 | 管什么 | 调坏的后果 |
|---|---|---|
| `learning_rate`（学习率） | 每棵树只走一小步 | 太大：来回震荡、分数乱跳；太小：要多得多的树 |
| `n_estimators`（树的数量） | 走多少步 | 太多：把训练集背下来（过拟合） |
| `max_depth` / `num_leaves` | 每棵树看多复杂的组合 | 太浅：学不到交互；太深：单棵树就开始背样本 |
| `min_child_samples` | 一个叶子至少几条样本 | 太小：噪声样本自成一个叶子 |

本教具用 `max_depth=1` 只是为了让每一步都手算得出来 —— **真实项目不会这么设**。
