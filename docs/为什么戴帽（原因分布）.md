# 为什么戴帽？—— 从 211 份公告正文里归类（这一格原来写的是「没答上来」）

> 上一版这里记的是「没答上来」：**标题不带原因**（① 组 46 条公告里只有 5 条标题提到机制），
> 巨潮详情页又是 JS 壳。现在补上了 —— 走**公告 PDF 正文**。
> 判据：`scripts/fetch_st_pdfs.py`（取正文）· `src/classify_st_reasons.py`（归类）· 读数 `data/st_reasons.csv`。

## 1. 怎么取到正文的

地址规律（实测）：`http://static.cninfo.com.cn/finalpage/<公告日>/<announcementId>.PDF`
—— `announcementId` 就在我们**早先存下的公告链接**里，所以不用再走检索 API。
按测试年样本里被戴帽的那批去重后取 **211 条**：成功 **206** · 缓存 3 · 失败 2（0.9%）· **正文中位 2,190 字**。

**归类前先定位「原因段」**（这一条是被自己上一版咬出来的）：

> ⚠️ 第一版直接在全文里搜关键词，命中的经常是**规则条文引用**而不是本案原因 ——
> 例：正文照抄「（三）财务会计报告被出具保留意见、无法表示意见或者否定意见的审计报告」，那是规则清单。
> 修法：先找锚点（`…的原因` / `主要原因` / `触及相关规定` / `触及《…》`）再在窗口内分类。
> **锚点覆盖率 141/209 = 67.5%**（找不到锚点的按全文分类）—— 一把尺要先自报量到多少比例。

## 3. 这一格回答了什么问题

**「没亏但被戴帽」的公司，绝大多数不是踩了财务指标，而是踩了治理 / 合规红线i**
（内控被出具否定或无法表示意见、收到行政处罚、账户被冻结、关联方资金占用、违规担保）。
证据句（每类一条，均取自正文原因段）：

- 内控被否 · `000010` 2026-04-29（①）：「…对公司 2025 年度财务内部控制进行审计，**出具了无法表示意见的内部控制审计报告**。根据《深圳证券交易所股票上市规则》…」
- 信息披露违法 · `002748` 2024-05-16（①）：「…收到**中国证监会相关行政处罚事先告知书**的，适用新规则第 9.8.1 条第八项关于虚假记载其他风险警示情形的规定…」
- 账户冻结 · `002731` 2026-02-07（①）：「…主要银行账户被人民法院**冻结**…属于主要银行账户被冻结的情形…」
- 资金占用 · `603008` 2026-04-25（①）：「…公司被控股股东及其关联人**非经营性占用资金**，余额达到最近一期经审计净资产绝对值 5% 以上…」
- 财务类（③ 组主流）· `002762` 2025-04-23（① 组的少数）：「…净利润 −4,531.68 万元为负值，**且扣除后的营业收入低于 3 亿元**…」

**⇒ 这解释了整条线的天花板**：触发"戴帽"的规则**有一大半不在财务报表里**（内控意见、行政处罚、账户冻结都是
**审计与监管的动作**）。所以任何只读财报比率的模型看不见它们 —— 这不是模型不够强，是**输入里没有那件事**。

## 4. 边界（别把这张表读过头）

- **① 组只有 45 条** ⇒ 每一格的分辨率约 ±7 个百分点，**只读量级、不读小数点**；
- **分类是关键词规则**，不是人工逐条读；锚点覆盖率 67.5%，**仍有规则条文混入的残余风险**
  （例：`300965` 那条的证据句落在「…10.3.1 条第一款第一项」上，更像规则引用）；
- 两个失败件（`300561` / `603825`，0.9%）没抓到正文，如实留在表里；
- 这条**不影响**先前任何模型读数 —— 它回答的是"这批样本为什么会被戴帽"，不是"能不能预测"。
